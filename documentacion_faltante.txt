T04. Gestión de Roles

T04.1 - Crear rol

Descomposición funcional "Crear rol"
1. El administrador selecciona el botón "Roles" en el menú principal.
2. El sistema abre la pantalla de gestión de roles mostrando todos los roles existentes en una grilla.
3. El administrador completa los campos de Nombre del rol, Descripción y selecciona las patentes y/o familias que desea asignar.
4. El administrador presiona el botón "Crear rol".
5. El sistema valida que el nombre no esté vacío y que tenga al menos una patente o familia asignada.
6. El sistema guarda el rol en la base de datos insertando sus vínculos con patentes y familias mediante una transacción.
7. El sistema registra la acción en la bitácora con criticidad "Alta".
8. El sistema actualiza la grilla y muestra el rol nuevo en pantalla.

4. El administrador selecciona las patentes y/o familias del rol en las listas de verificación.
5. El administrador presiona el botón "Crear rol".

Postcondiciones: El rol fue creado y está disponible para asignar a usuarios.

T06. Cambio de Contraseña

Descomposición funcional "Cambiar contraseña"
1. El usuario inicia sesión en el sistema.
2. El usuario selecciona el menú "Cambiar contraseña".
3. El sistema abre un formulario donde debe ingresar la contraseña actual, la nueva contraseña y la confirmación.
4. El usuario completa los campos y presiona "Confirmar".
5. El sistema valida que la nueva contraseña tenga al menos 8 caracteres, que la confirmación coincida y que la contraseña actual sea correcta.
6. El sistema encripta la nueva contraseña con SHA256 y la actualiza en la base de datos.
7. El sistema registra el cambio en la bitácora.
8. El sistema muestra un mensaje de éxito.

Diagrama de caso de uso "Cambiar contraseña"

Especificación de caso de uso "Cambiar contraseña"

Actor principal: Usuario (cualquier rol autenticado)
Actor secundario: -
Precondiciones: El usuario inició sesión en el sistema.
Puntos de extensión: -

Escenario principal:
1. El usuario selecciona "Cambiar contraseña" en el menú.
2. El sistema muestra el formulario con tres campos: contraseña actual, nueva contraseña y confirmación.
3. El usuario ingresa los datos.
4. El usuario presiona el botón "Confirmar".

6.1 - La confirmación no coincide: el sistema muestra un mensaje de advertencia.
7.1 - La contraseña actual es incorrecta: el sistema muestra un mensaje de error y no permite el cambio.
Postcondiciones: La contraseña del usuario fue actualizada en la base de datos.

T07. Bloqueo por Intentos Fallidos

El sistema implementa un mecanismo de seguridad que bloquea la cuenta de un usuario después de tres intentos fallidos de inicio de sesión.

Descripción del funcionamiento:
- Cada vez que un usuario ingresa una contraseña incorrecta, el sistema incrementa el campo IntentosFallidos en la tabla Usuarios.
- Cuando IntentosFallidos alcanza el valor 3, el sistema cambia automáticamente el estado del usuario a 0 (deshabilitado).
- El sistema registra cada intento fallido en la bitácora con criticidad "Media".
- Al alcanzar el bloqueo, registra un evento adicional con criticidad "Alta" indicando "Cuenta deshabilitada por intentos fallidos".
- Cuando el usuario bloqueado intenta iniciar sesión, el sistema muestra el mensaje: "Cuenta bloqueada. Contacte al administrador."
- El administrador puede rehabilitar la cuenta mediante el botón "Habilitar usuario" en la pantalla de gestión de usuarios, lo cual restablece el estado a 1 y los intentos fallidos a 0.
- En un inicio de sesión exitoso, si el usuario tenía intentos fallidos acumulados (menos de 3), el sistema los resetea a 0.

Tabla de base de datos:
- Columna IntentosFallidos INT NOT NULL DEFAULT 0 en la tabla Usuarios

T08. Dígito Verificador (Integridad de Datos)

El sistema incorpora un mecanismo de integridad que permite detectar si los datos de un usuario fueron modificados directamente en la base de datos, fuera del sistema.

Descripción del funcionamiento:
- Cada usuario tiene un campo DigitoVerificador (INT) en la tabla Usuarios.
- Este dígito se calcula como (suma de (posición + 1) * valor ASCII de cada caracter de DNI + NombreUsuario) % 10.
- Se calcula automáticamente al crear y modificar usuarios mediante DigitoVerificadorHelper.Calcular().
- En cada inicio de sesión, el sistema valida el dígito verificador almacenado contra el cálculo actual mediante DigitoVerificadorHelper.Validar():
  - Si no coincide, deniega el acceso y registra en la bitácora "Dígito verificador inválido detectado" con criticidad "Alta".
  - Muestra el mensaje: "Los datos del usuario fueron alterados. Contacte al administrador."
- El administrador dispone de herramientas en la pantalla de gestión de usuarios:
  - "Verificar integridad": compara el dígito almacenado con el calculado e informa si el usuario fue alterado o no.
  - "Regenerar dígito": recalcula y guarda el dígito correcto (útil después de una corrección manual en BD).
  - "Simular alteración": herramienta de prueba que deliberadamente guarda un dígito incorrecto para verificar que el mecanismo de detección funciona.

Clases involucradas:
- DigitoVerificadorHelper (Servicios): métodos Calcular(dni, nombreUsuario) y Validar(usuario).
- UsuarioBLL (BLL): métodos VerificarIntegridad(dni), SimularAlteracion(dni) y RegenerarDigitoVerificador(dni).

T09. Arquitectura - Patrones de Diseño

T09.1 - Singleton (SessionManager)
- La clase SessionManager garantiza una única instancia en toda la aplicación.
- Implementa doble verificación con lock para seguridad en entornos multi-hilo (double-checked locking).
- Almacena el usuario autenticado y sus permisos durante toda la sesión.
- Métodos: Login(usuario), SetPermisos(permisos), Logout().

T09.2 - Observer (LocalizationService)
- La clase LocalizationService actúa como sujeto observable (singleton).
- La interfaz ILocalizationObserver define el contrato con el método OnLanguageChanged().
- Cada formulario se suscribe al servicio mediante Subscribe(this) en su constructor y se desuscribe en OnFormClosed.
- Al cambiar el idioma con SetLanguage(), el servicio notifica a todos los observadores llamando a OnLanguageChanged().
- Utiliza WeakReference para evitar fugas de memoria cuando los formularios se cierran sin desuscribirse.

T09.3 - Composite (Roles y Familias de Permisos)
- IComponentePermiso: interfaz componente que define Id, Nombre, Descripcion y ObtenerPatentes().
- PatenteComponent: hoja del árbol, devuelve su propio ID como permiso individual.
- FamiliaComponent: compuesto que contiene una lista de hijos (IComponentePermiso) y delega la obtención de patentes mediante SelectMany().Distinct().
- RolBE: cliente del composite. Contiene una lista de componentes (patentes sueltas o familias completas) y los recorre recursivamente con ObtenerTodasLasPatentes().
- La construcción del árbol se realiza en RolesDAL.ObtenerRolConPermisos(), que arma la estructura completa desde las tablas Rol_Pat, Rol_Fam y Fam_Pat.

T09.4 - Facade (Permisos)
- La clase Permisos simplifica la interacción con el árbol de permisos composite.
- Provee métodos: Tiene(idPatente), TieneAlguna(ids), TieneTodas(ids).
- Los formularios llaman a SessionManager.GetInstance.Permisos.Tiene(Patente.GestorUsuarios) sin conocer la estructura interna del composite.


T10. Smoke Tests (Pruebas Integradas)

El menú principal incluye seis botones de prueba visibles para el administrador al marcar el checkbox "Mostrar pruebas". Estas pruebas ejercitan el ciclo de vida completo de un usuario de prueba fijo (DNI 90000001, nombre de usuario "Prueba90000001") para verificar que todos los componentes del sistema funcionan correctamente:

1. "Prueba crear usuario": crea el usuario de prueba si no existe.
2. "Prueba login": inicia sesión con el usuario de prueba.
3. "Prueba desbloquear": habilita la cuenta del usuario de prueba (si fue bloqueada).
4. "Prueba modificar usuario": modifica los datos del usuario de prueba.
5. "Prueba cambiar clave": cambia la contraseña del usuario de prueba.
6. "Prueba logout": cierra la sesión del usuario de prueba y restaura la sesión del administrador.

Cada prueba se ejecuta sin afectar la sesión activa del administrador gracias al helper EjecutarSinAfectarSesion(), que guarda y restaura el usuario y permisos originales.
